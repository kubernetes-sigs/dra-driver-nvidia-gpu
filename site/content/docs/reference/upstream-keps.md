The DRA Driver for NVIDIA GPUs builds on a set of upstream
[Kubernetes Enhancement Proposals (KEPs)](https://github.com/kubernetes/enhancements).
This page maps each upstream KEP to the driver behavior it enables, where that
behavior lives in the driver, and the first driver release that included it.
For the Kubernetes versions and Kubernetes feature gates that each driver
feature gate requires, see [Feature gates](feature-gates.md).

## KEPs implemented by the driver

| [KEP-4815: Partitionable devices](https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/4815-dra-partitionable-devices) | `ResourceSlice` `sharedCounters`, `devices[].consumesCounters` | Enables Dynamic MIG. Each physical GPU is a counter set, and each possible MIG device consumes counters from it, so the scheduler cannot select overlapping MIG placements. Kubernetes v1.34 requires counters and devices in the same `ResourceSlice`, while v1.35 and later require separate slices; the driver detects the Kubernetes version and publishes the matching layout. See [MIG](../guides/gpu-allocation/mig.md). | [`partitions.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/partitions.go), [`driver.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/driver.go), [`device_state.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/device_state.go) | [v25.12.0](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases/tag/v25.12.0) (`DynamicMIG` gate) |
| [KEP-5018: AdminAccess](https://github.com/kubernetes/enhancements/tree/master/keps/sig-auth/5018-dra-adminaccess) | `ResourceClaim` `adminAccess` | Admin-access allocations can overlap a full GPU that is already allocated to a workload, and are not counted as device consumption. Since v0.5.0, the driver rejects admin access on anything other than a full GPU, and rejects any driver configuration that applies to an admin-access request. | [`prepared.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/prepared.go), [`device_state.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/device_state.go) | [v25.12.0](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases/tag/v25.12.0) |

MIG and VFIO DeviceClasses are not mapped. The Helm chart sets `extendedResourceName` only when it renders the DeviceClass with the `resource.k8s.io/v1` API. | [`deviceclass-gpu.yaml`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/deployments/helm/dra-driver-nvidia-gpu/templates/deviceclass-gpu.yaml) | [v25.12.0](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases/tag/v25.12.0) |

| [KEP-6072: Standard numaNode attribute](https://github.com/kubernetes/enhancements/tree/master/keps/sig-node/6072-dra-standard-numanode) | `ResourceSlice` attribute `resource.kubernetes.io/numaNode` | Publishes the standard NUMA attribute on full GPU, MIG, and VFIO devices, so other DRA drivers can align devices with `matchAttribute` constraints. Before v0.5.0, the driver published a driver-specific `numa` attribute instead; update CEL selectors that reference `numa` when you upgrade. See [NUMA locality](resourceslice-attributes.md#numa-locality). | [`numa.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/numa.go), [`deviceinfo.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/deviceinfo.go), [`nvlib.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/nvlib.go) | [v0.5.0](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases/tag/v0.5.0) |
| [KEP-5491: List types for attributes](https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/5491-dra-list-types-for-attributes) | List-valued `ResourceSlice` attributes | Publishes `resource.kubernetes.io/numaNode` as a one-element list instead of a scalar. This is scheduler accounting, not GPU memory or compute isolation. It is separate from time-slicing and MPS, and the driver rejects MPS sharing when `ConsumableShares` is enabled. See [Consumable capacity](../guides/gpu-allocation/consumable-capacity.md). | [`consumable_shares.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/consumable_shares.go), [`device_state.go`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/blob/main/cmd/gpu-kubelet-plugin/device_state.go) | [v0.5.0](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases/tag/v0.5.0) (`ConsumableShares` gate) |

## KEPs used without driver-specific code

These KEPs are implemented by Kubernetes components and work with the driver's
published devices without any driver changes.

| Upstream KEP | Component / API area | Relevance to `dra-driver-nvidia-gpu` |
| --- | --- | --- |
| [KEP-4816: Prioritized list](https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/4816-dra-prioritized-list) | `ResourceClaim` `firstAvailable` | A request can list ordered alternatives, such as a specific GPU model first and a MIG device as a fallback. The scheduler evaluates the alternatives. |
| [KEP-3695: PodResources API for DRA](https://github.com/kubernetes/enhancements/tree/master/keps/sig-node/3695-pod-resources-for-dra) | Kubelet PodResources gRPC API | Reports DRA allocations to node-local monitoring agents. [dcgm-exporter](https://github.com/NVIDIA/dcgm-exporter) uses it to attribute GPU metrics to Pods, and supports `resource.k8s.io/v1beta1` starting with release 4.3.1-4.4.0 and `resource.k8s.io/v1` starting with release 4.6.0-4.8.3. |
